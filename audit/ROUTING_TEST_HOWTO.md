## 1. 게시판 제목을 그대로 넣으면 비관적으로 나옵니다

처음에 네이버 카페 글 제목 202개·195개를 그대로 `search_topics`에 넣어 쟀습니다. 0건이 21~27% 나왔습니다.

그런데 게시판 제목은 사람이 상담창에 치는 말이 아닙니다.

```
게시판 제목:   "[개인]수정조정신청하려면..."
카톡에 칠 말:  "채무조정 받고 있는데 조건을 바꾸고 싶어요"
```

`[개인]` 같은 말머리, 말줄임표, 명사형 종결은 게시판 문법입니다. 축약돼 있어서 매칭이 덜 되고, **0건이 실제보다 부풀려집니다.** 위 표에서 제목은 0건 16개인데 카톡 발화는 9개였습니다.

동시에 **오답은 과소평가됩니다.** 제목에는 범용어가 없어서 노이즈 매칭이 잘 안 일어납니다(제목 기준 오답 0개).

## 2. 실사용 경로는 `triage` 하나가 아닙니다 — `get_procedure` 직접 호출이 더 흔했습니다

> **정정(2026-09-08).** 이 항목은 처음에 "호스트 LLM이 발화를 요약해 `triage`에 넣으므로, 요약문이 범용어를 붙여 오답을 만든다"고 적었습니다. **프리뷰에서 실제로 확인해 보니 전제가 틀렸습니다.** 아래로 교체합니다.

프리뷰(`preview-chatgpt.kakao.com`)에서 8건을 돌려 어떤 도구가 불리는지 봤습니다.

| 발화 | 호출된 도구 | 결과 |
|---|---|---|
| 디자인 외주 끝냈는데 잔금을 안 줍니다 | `get_procedure` | 물품용역대금미수금 ✅ |
| 명도일이 다가오는데 어떻게 해야하나요 | `get_procedure` | 건물인도(명도)청구 ✅ |
| 윗집 층간소음 때문에 너무 힘들어요 | `get_procedure` | 층간소음분쟁 ✅ |
| 채무조정 수정조정 신청하고 싶은데 | `get_procedure` | 신용회복위원회채무조정 ✅(근사) |
| 친구한테 빌려준 돈 못 받았어 | `triage` | 대여금미반환 ✅ |
| 법원에서 뭐가 날아왔는데 | **없음** | — |
| 법원에서 보정명령 왔는데 뭘 해야해요 | **없음** | — |
| 카드값 밀렸는데 연체 기록 남나요 | **없음** | — |

**5건 중 4건이 `get_procedure` 직접 호출이었습니다.** `get_procedure`의 `topic`은 279개짜리 enum이라, 호스트 LLM이 목록에서 직접 고릅니다. **이 경로는 `rankTopics`를 아예 거치지 않습니다.**

즉 `search_topics`/`triage`만 테스트하면 실사용의 일부만 보는 것입니다. **`get_procedure`의 enum에 그 주제가 있는지, 이름이 알아볼 만한지가 라우팅만큼 중요합니다.**

### 요약문의 실제 모습

`triage`가 불릴 때 넘어가는 `situation`은 위젯 부제목에 그대로 보입니다. 관측된 것:

```
"임대차계약 종료 후 명도일이 다음 주인데 임대인이 보…"
"프리랜서 디자인 외주를 6주간 수행하고 전부 납품했으…"
"프리랜서 공동계약에서 공동업무 상대방의 미이행으로 내…"
```

**사실을 압축한 서술문**이고, `~문의`·`~대응 방법` 같은 명사형으로 끝나지 않습니다. 처음에 이 문서가 걱정했던 형태가 아닙니다.

다만 실사용 대화에서 `"법원에서 보정명령을 받았고 요구사항이 매우 많아 대응 방법을 알고 싶음"` → **렌터카사고분쟁**이 나온 사례가 한 건 있습니다(`대응`이 렌터카 주제 제목에 있어 +4). 요약이 길어지면 이런 일이 생길 수 있으니, `triage`를 볼 때 요약문 형태로도 한 번 넣어보는 것은 여전히 쓸모가 있습니다. **다만 명사형 요약을 지어내서 재면 실제보다 나쁘게 나옵니다** — 그렇게 쟀다가 오답 8건을 잘못 보고했습니다.

## 3. 프리뷰로 잴 때는 ChatGPT 메모리를 꺼야 합니다

프리뷰는 실제 ChatGPT 계정으로 로그인됩니다. **"새 대화 시작"은 화면만 지우고 계정 메모리는 지우지 않습니다.**

같은 발화가 이렇게 갈렸습니다.

| 발화 | 메모리 켠 상태 | 메모리 끈 상태 |
|---|---|---|
| 디자인 외주 끝냈는데 잔금을 안 줍니다 | **도구 호출 없음** | `get_procedure` → 물품용역대금미수금 ✅ |
| 명도일이 다가오는데 어떻게 해야하나요 | **도구 호출 없음** | `get_procedure` → 건물인도(명도)청구 ✅ |

오염을 알아챈 계기는, `"법원에서 뭐가 날아왔는데"`만 쳤는데 답변이 **"보정명령이면 일단 내용부터 정확히 봐야 해요"** 로 시작한 것입니다. `보정명령`은 세 대화 전에 물었던 말이었습니다.

**끄는 법**: `chatgpt.com` → 설정 → 개인 맞춤 설정 → **메모리 사용 끄기** + **저장된 메모리 삭제**. 끄기만 하면 기존 메모리가 남아 있을 수 있습니다. (사이드바에 대화 목록이 쌓이는 것은 별개이고 측정에 영향이 없습니다.)

**이걸 모르고 재면 호출률이 실제보다 나쁘게 나옵니다.**

## 4. 0건 개수는 지표로 쓰기 어렵습니다


0건을 줄이는 가장 쉬운 방법이 "아무 데나 보내기"입니다. 그래서 0건만 보면 개선처럼 보입니다.

실제로 `hay`(점수 계산 대상 문자열)에 `단계`·`비고` 필드를 추가하는 실험을 했습니다.

```
0건        52 → 46   (6개 줄어듦)
기존 테스트  244개 전부 통과
실제 변화   13개 중 8개가 나빠짐
```

나빠진 것:
```
(0건)    → 압수수색적법성       성질 못 참고 화를 표시하게되면
(0건)    → 공무원불친절부당대우   신속 실효 중에 햇살론 카드 쓸 수 있나요?
(0건)    → 대출빙자형          신용회복중입니다. 완제 후 대출 문의
새출발기금  → 국가장학금_학자금대출  새출발 부실우려 진행중인데 추가 대출
개인회생   → 불법추심대응        [회생]금지명령 안나왔는데
```

**제안**: 정답 / 0건 / 오답 **셋으로 나눠 셉니다.** 0건은 "찾지 못했습니다"라는 무응답이고, 오답은 틀린 절차로 보내는 오안내입니다. 성격이 다릅니다.

## 5. `npm test` 통과가 안전을 보장하지는 않았습니다

위 실험에서 **244개가 전부 통과했는데 8건이 나빠졌습니다.** 기존 테스트는 이미 알고 있는 케이스를 지키는 것이라, 처음 보는 발화에서 생기는 회귀는 잡지 못합니다.

**제안**: 라우팅을 바꿨으면 실사용 발화 세트로 **변경 전후 1순위를 하나씩 비교(diff)** 합니다. 총계만 보면 좋아진 것과 나빠진 것이 상쇄되어 안 보입니다. 위 실험도 총계로는 개선이었습니다.

```
# 전후 비교의 최소 형태
변경 전 결과를 JSON으로 저장 → 코드 수정 → 같은 입력으로 다시 → 1순위가 달라진 것만 출력
```

## 7. 커뮤니티 글로 검증할 때

수집 스크립트의 방침은 `scripts/NAVER_CAFE_SCRAPER.md`에 있습니다 — 수집물은 `.gitignore` 대상이고, 주제·동의어 데이터에 원문을 넣지 않습니다.

**제안**: 테스트에 넣을 때도 원문 그대로보다 표현 패턴만 가져와 다시 쓰는 편이 안전합니다. 어차피 게시판 제목은 위 1번 이유로 실사용과 다르므로, 카톡 말투로 바꿔 쓰는 것이 검증 정확도에도 낫습니다.

### 수집 시 정렬 기준

좋아요순으로 뽑으면 **정보공유·후기·팁만 올라옵니다.** 질문글에는 좋아요가 붙지 않습니다.

```
좋아요순 202개 → 좋아요 중앙값 11 · 최대 839 · 0인 글 3개
최신순  195개 → 좋아요 중앙값  0 · 최대  14 · 0인 글 131개
```

스크래퍼 기본값을 최신순으로 바꿨습니다(`python collect_ccrs5500_top.py 50 RECENT out.json`).

## 8. `find_topic_gaps.py`는 "파일에 글자가 있나"만 봅니다

`scripts/find_topic_gaps.py`는 수집한 제목을 토큰화해 **`src/data/*.ts` 전체 텍스트에 없는** 고빈도 낱말을 뽑습니다. 발화를 지어내지 않아도 되므로 새 분야를 볼 때 먼저 돌리면 좋습니다.

```python
gaps = [(w, c) for w, c in counter.items()
        if c >= MIN_FREQ and w not in known]   # known = src/data/*.ts 전체
```

다만 판정이 **단순 문자열 포함 검사**라 두 가지를 놓칩니다.

### 다른 뜻으로라도 글자가 있으면 빠집니다

`실효`는 `src/data`에 34번 나옵니다 — 전부 `형실효_범죄경력`(전과 말소)입니다. 채무조정의 `실효`(조정 취소)와 **뜻이 정반대인데 글자가 같아** "있음"으로 판정되어 빈틈 목록에서 빠집니다. 실제 결과에도 `실효`가 아니라 `실효후`만 떴습니다.

### "있다"와 "닿는다"가 다릅니다

세 층이 있습니다.

| 층 | 확인 방법 | 보정명령의 경우 |
|---|---|---|
| ① 파일에 글자가 있나 | `find_topic_gaps.py` | ✅ 1건(`민사소송소장`의 `비고`) |
| ② 그 주제로 라우팅되나 | `search_topics` 1순위 | ❌ 0건 |
| ③ 도착지 본문에 답이 있나 | `get_procedure` 응답 확인 | ❌ 개인회생 본문에 없음 |

도구는 ①만 봅니다. `보정명령`·`예납금`·`햇살론`은 모두 파일에 1건씩 있어 빈틈 목록에서 빠졌지만, **셋 다 검색으로는 0건**입니다. 점수 계산이 `제목`·`분야`·`적용대상`+`근거법`만 쓰고 `비고`·`단계`는 안 보기 때문입니다.

### 그래서 순서

```
1. find_topic_gaps.py 로 후보 뽑기        ← 지어내지 않음, 편향 없음
2. 그 낱말을 search_topics 에 실제로 넣기   ← ②를 확인
3. 닿으면 get_procedure 응답을 읽기       ← ③을 확인
```

**도구는 후보를 주고, 확인은 직접 넣어봐야 합니다.** 도구가 "있음"이라고 한 것도 0건일 수 있습니다.

### 노이즈

기본 `STOPWORDS`가 짧아 어미·활용형이 빈틈으로 잡혔습니다(150개 기준 상위 14개 중 9개). 2026-09-08에 `궁금합니다`·`되나요`·`중인데` 등 30개를 보강해 14 → 6으로 줄였습니다. 새 분야에서 또 새 어미가 나오면 그때 추가하면 됩니다.

남은 노이즈는 토큰화 한계입니다 — 정규식이 `[가-힣]{2,}`라 `회생 1차서류`가 `차서류`가 되고 `대출금이`에서 조사가 안 떨어집니다. 6개 중 2개꼴이라 눈으로 걸러도 됩니다.

## 9. 두 어절 동의어는 사이에 말이 끼면 붙지 않습니다

동의어는 공백을 지운 뒤 **연속 부분문자열**로 봅니다. 그래서 `"남편이 때"`는 `"남편이 때려요"`에는 붙지만 `"남편이 **자꾸** 때리는데"`에는 붙지 않습니다.

실제로 두 번 겪었습니다.

| 언제 | 무엇 |
|---|---|
| 2026-08-23 | 스토킹 — `"계속 친한 척 연락함"`이 0건. 테스트에 *"사이에 말이 끼어도 잡는다"* 로 남아 있습니다 |
| 2026-09-08 | 가정폭력 — `"남편이 자꾸 때리는데"`가 0건. 주제가 넷이나 있는데 닿지 못했습니다 |

### 얼마나 많은지 재봤습니다

두 어절짜리 동의어 513개 중 43개를 뽑아, 두 어절 사이에 `자꾸`를 끼워 넣고 결과가 달라지는지 봤습니다.

```
유지 19  ·  달라짐 24  (56%)
```

**다만 이 56%는 상한선입니다.** 끼워 넣은 말이 어떤 구에는 부자연스럽습니다(`"차에 자꾸 치어"`, `"혼자 자꾸 일하는"`). 실제 사용자가 그렇게 쓰지는 않습니다. 확실한 것은 **현상이 실재하고, 두 어절 동의어가 전체의 41%(513/1241)** 라는 것입니다.

### 그래서 동의어를 쓸 때

- **가능하면 한 어절**로 씁니다. `"보호명령"`·`"임시조치"`·`"압류방어"`처럼요.
- 두 어절이 꼭 필요하면 **사람이 실제로 끼워 넣는 말을 함께 넣습니다**. `"남편이 때"` 하나가 아니라 `"남편한테 맞"`·`"집에서 폭력"`처럼 다른 경로도 같이 둡니다.
- 새 동의어를 넣은 뒤 **사이에 `자꾸`·`계속`·`아직`을 끼워 한 번 더 돌려봅니다.** 5초면 됩니다.

근본 수정은 매칭 로직(연속 부분문자열)을 바꾸는 일이라 이 문서에서는 다루지 않았습니다.

## 10. 전수 자가진단을 테스트로 넣었습니다 — `npm test`가 못 잡는 회귀를 잡습니다

**주제 자신의 제목을 넣어 자기 주제로 돌아오는지** 279개 전부 확인합니다. 발화를 지어내지 않아도 되고, 4~5초면 끝납니다.

```bash
npx vitest run test/server.test.ts -t "자가진단"
```

### 왜 필요했나

2026-09-08에 가정폭력 동의어로 `"보호명령"`을 넣었더니 아동학대의 **`피해아동보호명령`까지 삼켰습니다.** 그런데 그때 `npm test` **253개가 하나도 잡지 못했습니다.** 전수 진단에서만 드러났습니다.

동의어를 넓히면 **예상하지 못한 주제를 뺏습니다.** 기존 테스트는 이미 아는 케이스만 지키므로, 처음 보는 조합에서 생기는 회귀는 구조적으로 못 잡습니다.

테스트가 실제로 그 회귀를 잡는지 확인했습니다 — 아동학대 항목을 도로 빼니 이렇게 나옵니다.

```
새로 생긴 자가진단 실패 1개
  ✗ 아동학대피해아동보호명령  →  가정폭력피해자보호명령  ("피해아동보호명령 청구")
```

### 쓰는 법

테스트 안에 `알려진실패` 목록이 있습니다(현재 15개). **여기 없는 이름이 새로 뜨면 그건 회귀입니다.** 고쳐서 목록에서 빠지는 것은 환영이고, 그때는 배열에서 지우면 됩니다.

```
전수 진단 실패:  18 → 16 (특칙 주제 수정) → 15 (아동학대 회귀 수정)
```

### 한계

자기 제목으로 자기를 찾는 것뿐이라 **사람이 실제로 쓰는 말은 보지 못합니다.** 카페 발화 검증을 대신하지 못하고, 회귀 감시용입니다. 둘 다 필요합니다.

## 11. ★ 로컬 수치는 실사용의 일부에만 해당합니다 — 경로를 재봤습니다

이 문서의 다른 항목들이 전부 이 사실 위에 있습니다. **프리뷰 17건(ChatGPT 메모리 끈 상태)에서 어떤 경로로 가는지 셌습니다.**

| 경로 | 건수 | `rankTopics`(동의어) 관여 |
|---|---|---|
| `get_procedure` 직접 호출 | 8 | ❌ **우회** — 모델이 279개 enum에서 직접 고름 |
| `triage` · `search_topics` | 3 | ✅ **사용** |
| 도구 호출 없음 | 6 | ❌ 무관 |

```
호출률          11/17 (65%)
호출 시 정확도   11/11 (100%)
rankTopics 관여  3/17 (18%)
```

### 그래서 동의어 수정의 값어치는

**실사용 6건 중 1건꼴에만 관여합니다.** 로컬에서 `search_topics` 500개를 고쳐도 실사용에서는 그 비율만큼만 작동합니다.

무의미하지는 않습니다.

- `triage`가 불린 3건은 **전부 정확**했습니다(보증금반환·스토킹·대여금)
- `triage`는 도구 설명이 *"무조건 이 도구부터 호출하세요"* 로 가장 강하게 미는 입구입니다
- **주제가 덜 알려진 것일수록** 모델이 enum에서 못 찾고 `triage`로 갈 가능성이 큽니다. 지금 고치고 있는 것들이 대부분 그런 것입니다(수정조정·명도·과실좀·긴생비)

### 그리고 도구가 안 불려도 답은 대체로 맞습니다

`"부모님이 돌아가셨는데 빚이 재산보다 많아요"` — 도구는 안 불렸는데 ChatGPT 답변에 **상속포기·한정승인·"안 날부터 3개월"** 이 다 있었습니다.

**이 서비스의 값어치는 "답을 아는 것"이 아니라 그 위에 얹는 것입니다.**

```
접수처 바로가기 버튼 · 132 전화 버튼 · 서식 실물(HWPX)
인지대·송달료 계산 · 검증된 조문·판례 인용 · 기한 배지
```

`"회사에서 두 달째 월급을 안 줍니다"`에서 실제로 그게 다 나왔습니다 — 소멸시효 3년 배지, 관할 노동청, 5단계 절차, 접수처 바로가기·132 버튼.

### 잴 때 이렇게 하시면 됩니다

```
로컬 search_topics 500개   →  빠르고 싸다. 어휘 빈틈을 찾는 데는 이만한 게 없다
프리뷰 10~20건            →  느리다(건당 45초). 경로와 최종 결과를 본다
```

**로컬로 넓게 훑고 프리뷰로 확증합니다.** 로컬 수치만 보고하면 실사용을 과대평가하게 됩니다.

### 프리뷰를 여러 개 동시에 돌릴 수 있나

- **API 직접 호출은 하지 않습니다.** 채팅이 `chatgpt.com/backend-api/c/conversation`으로 가고 `sentinel.openai.com`(봇 차단)이 붙어 있습니다. 우회는 선을 넘습니다.
- **탭 여러 개는 되지만 권하지 않습니다.** 탭을 오갈 때마다 스냅샷 전체가 딸려와 오히려 비쌉니다. 실제 병목은 대기 시간이 아니라 왕복 횟수입니다.

## 한 줄 정리

**게시판 제목으로 재면 0건이 부풀고 오답이 숨습니다. 실사용은 `triage`뿐 아니라 `get_procedure` 직접 호출로도 갑니다. 프리뷰로 잴 때는 ChatGPT 메모리를 끄고, 0건만 보지 말고 정답·0건·오답 셋으로 세고, 바꾸기 전후를 하나씩 비교합니다.**

그리고 **추측한 입력으로 재지 않습니다.** 이 문서 자체가 그 실수를 두 번 했습니다 — 게시판 제목으로 쟀다가 한 번, 지어낸 요약문으로 쟀다가 한 번. 둘 다 실제로 확인하고 나서야 틀린 걸 알았습니다.
