`물품용역대금미수금`("물건값·일한 대금을 못 받았을 때")은 멀쩡히 있는데, **거기로 가는 말이 없습니다.**

|---|---|

| 외주 / 외주업체 / 외주비 | 물품용역대금미수금 · 채무불이행 |

**0건 자체는 버그가 아니라 설계대로 동작한 것입니다.** 근거가 없으면 답하지 않는 쪽이 맞습니다(`CLAUDE.md` 절대규칙 1). 게이트를 푸는 게 아니라 데이터를 채우는 문제로 보입니다.

## 2) 어절을 조사째로 substring 매칭합니다

`words`가 공백으로만 쪼갠 어절이고, 이것을 `적용대상` 문장에 그대로 `includes`로 겁니다.

실제 사건 전문에 대한 점수입니다.

```
재판이혼    ← "상대방이"(+2) "자기"(+2)      = 4점 / 근거 2개
채무불이행  ← "상대방이"(+2) "이행하지"(+2)  = 4점 / 근거 2개   ← 동점
```

동점이라 데이터 파일 등록 순서로 1등이 갈립니다. **"상대방이"·"자기"·"않고"·"대신"** 같은 조사 붙은 기능어가 근거로 잡히고, `weak >= 2` 게이트를 **그 둘만으로** 통과합니다.

주석에 남아 있는 전적(계속→헬스장, 연락→불법추심, 업무누락→보이스피싱)과 같은 계열이고, 한 겹 아래입니다.

## 3) `hay`에 근거법 전문이 들어가 긴 주제가 유리합니다

```ts
const hay = `${p.적용대상} ${p.근거법.join(" ")}`;
```

# 라우팅과 별개로 드러난 커버리지 구멍

라우팅을 고쳐서 `채무불이행`·`물품용역대금미수금`으로 제대로 보내더라도, **그 다음에 줄 것이 비어 있습니다.** 위 사건(공동수급자 미이행 → 대신 이행 → 실비 청구)을 끝까지 따라가며 확인했습니다.

## 1) 동업·조합 관계를 다루는 주제가 없습니다

| 확인한 것 | 결과 |
|---|---|
| 주제 키에 `동업\|조합\|공동\|구상\|정산` | ❌ 없음 |
| 조합 규정(민법 제703~724조)을 근거법에 쓴 주제 | `교통사고손해배상청구` 1건뿐(제724조 직접청구권) |
| '동업'이라는 말이 나오는 주제 | `연대보증채무대응` 1건 — 그것도 **보증인보호법 제2조의 적용제외 사유**("동업자 보증")로만 |

5:5 공동계약에서 한쪽이 이행하지 않았을 때의 정산·구상은 `채무불이행`으로 **근사할 수 있을 뿐** 정조준하는 주제가 없습니다. 조합 관계라면 민법 제712조(손실부담)·제713조(무자력 조합원의 채무)가 걸리는데 어느 주제에서도 다루지 않습니다.

덧붙여, 이용자가 "동업자가…"로 말을 시작하면 그 말이 실제로 존재하는 유일한 곳이 `연대보증채무대응`의 근거법이라는 점도 오라우팅과 무관하지 않아 보입니다.

## 2) 대금 청구 주제에 연결된 서식이 0개입니다

```
물품용역대금미수금 → 연결 서식 ❌ 없음
채무불이행         → 연결 서식 ❌ 없음
```

두 주제 모두 `get_procedure` 응답의 진행 지침에 이렇게 나갑니다.

```
- 이 주제에는 제공할 표준 서식이 없다. get_form_template을 호출하지 말고,
  서식을 지어내지도 말 것.
```

지어내지 않는 것은 옳습니다. 다만 **서식 실물이 이 서비스의 차별점인데, 돈 받아내는 경로에서만 비어 있습니다.**

## 3) 서식은 있는데 닿지 않습니다 — 매핑이 1:1입니다

`FORM_TOPIC`이 `서식 → 주제` 1:1 구조라(`src/server.ts:141`), 서식 하나가 여러 주제에 걸리지 못합니다.

| 서식 | 현재 걸린 주제 | 대금 주제에서 |
|---|---|---|
| `지급명령신청서` | `지급명령` | ❌ 안 나옴 |
| `소액소송_소장` | `소액사건소송` | ❌ 안 나옴 |
| `손해배상청구_소장` | `손해배상청구` | ❌ 안 나옴 |

이용자가 "잔금을 못 받았다"에서 출발하면 `물품용역대금미수금`에 도착하는데, 정작 필요한 `지급명령신청서`는 **주제를 한 번 더 갈아타야** 나옵니다.

## 4) 없는 서식 — 용역대금·미수금 내용증명

현재 내용증명 서식 10종입니다.

```
임금지급 · 보증금반환 · 대여금반환 · 교통사고_손해배상 · 수선요구
장충금반환청구 · 계약해제 · 부동산매매_해제 · 상가_갱신요구 · 개물림_손해배상
```

**용역대금·미수금·외주비 청구용이 없습니다.** `채무불이행` 절차의 2단계가 "내용증명 이행 최고(기한 없는 채무는 최고로 지체 발생)"이고 민법 제397조상 금전채무는 최고 시점이 지연이자 기산점이 되는데, 정작 그 단계에서 내밀 서식이 없습니다. 이용자가 실무에서 가장 먼저 필요로 하는 문서입니다.

## 우선순위에 대한 의견

라우팅 수정은 **잘못된 안내를 없애는 일**이고, 커버리지는 **줄 것을 만드는 일**입니다. 잘못된 안내를 먼저 없애는 순서가 맞다고 봅니다. 다만 라우팅만 고치면 "맞는 주제에 도착했는데 서식이 없다"로 끝나므로, 최소한 3)의 매핑 문제는 함께 보는 것이 좋겠습니다. 서식을 새로 만들지 않고 연결만 바꾸면 되는 부분입니다.

# ⛔ 결정이 필요한 것 — 위기 표현이 채무 상담에 묻힙니다 (구현하지 않았습니다)

채무 카페(`ccrs5500`·`cafe20135031`) 실사용 제목 202개를 라우팅에 돌려보다 나왔습니다. **코드는 건드리지 않았습니다.** 혼자 판단할 사안이 아니라고 보아 근거만 정리합니다.

## 무슨 일이 일어나고 있나

`자살위기_도움받기` 주제는 **이미 있습니다.** 내용도 적절합니다 — 112·119, 자살예방 상담 **109**(24시간·비밀보장), 정신건강 위기상담 1577-0199, 자살시도자 치료비 지원.

그런데 **이 주제로 가는 동의어가 하나도 없습니다.** `"자살"`이라고 직접 써야만 걸립니다.

| 발화 | 현재 결과 |
|---|---|
| 자살 | 자살위기_도움받기 ✅ |
| 죽고 싶어요 | **(0건)** |
| 살고 싶지가 않아요 | **(0건)** ← 채무 카페에 실제로 올라온 제목입니다 |
| **빚 때문에 죽고 싶어요** | **개인회생** ⚠️ |

마지막 줄이 가장 나쁩니다. `빚` 신호가 이겨서 **위기 신호가 통째로 묻힙니다.** 채무 상담 서비스에서 드물지 않게 마주칠 조합입니다.

## 검토한 방법과, 그것을 넣지 않은 이유

주제 경쟁(`rankTopics`)에 위기 주제를 넣으면 채무 안내가 밀려나므로, **주제는 그대로 두고 안내문 앞에 도움처 한 줄을 얹는** 방식을 검토했습니다(`triage` 핸들러 6줄, 전화번호는 `PROCEDURES["자살위기_도움받기"].온라인접수`에서 읽음). 라우팅과 기존 테스트에는 영향이 없습니다.

그런데도 넣지 않았습니다. **다음 위험을 지시문으로는 보장할 수 없기 때문입니다.**

> 도움처를 앞세우면 호스트 LLM이 "전문가 상담을 받으세요"로 마무리하고 **원래 채무 안내를 하지 않을 수 있습니다.** 빚 문제는 그대로 남는데 안내는 사라집니다.

우리가 넣는 것은 강제가 아니라 지시문이고, 화면 카드에 번호가 박히는 구조도 아닙니다. **"둘 다 나간다"를 보장할 수단이 지금 구조에는 없습니다.** 이 실패는 절대 일어나서는 안 되는 종류라고 판단해 구현을 보류했습니다.

## 함께 측정한 것 — 단어 목록 방식의 한계

위기 표현 판별을 정규식/단어 목록으로 하면 어디까지 잡히는지 실제로 재봤습니다.

| 잡아야 하는데 놓침 | 잡으면 안 되는데 걸림 |
|---|---|
| 살고 싶지가 않아요 | 죽고 싶을 만큼 화나요 |
| 그만 살고 싶어요 | 자살골 넣었어요 |
| 사라지고 싶어요 | |
| 다 끝내고 싶어요 | |

`살고 싶지"가" 않아요`는 조사 하나 때문에 빠집니다. **완곡한 표현일수록 위험한데, 단어 목록은 그쪽을 가장 못 잡습니다.** 목록을 늘려도 끝이 없습니다.

## 결정이 필요한 지점

1. **다루는가** — 지금은 0건이라 우리 쪽에서 아무것도 나가지 않습니다(호스트 LLM 자체 대응에 전적으로 의존). 그대로 두는 것도 선택지입니다.
2. **다룬다면, "둘 다 나간다"를 어떻게 보장하는가** — 위젯 카드에 도움처를 함께 싣는 방법 등, 지시문에 의존하지 않는 수단이 필요해 보입니다.
3. **한계를 어디에 적는가** — 넣기로 한다면 "완곡한 표현은 잡지 못하며 최종 안전망이 아니다"를 문서에 남겨야 합니다. 놓쳐도 헛나가도 로그에 남지 않고 아무도 신고하지 않는 종류라, 넣었다는 사실만으로 안심하게 되는 것이 가장 큰 위험입니다.

# 참고

- 판단은 `search_topics` 1순위 기준입니다. `triage`도 같은 `rankTopics`를 씁니다.
- 기대 주제를 넉넉하게 잡았습니다. 좁게 잡으면 통과율이 더 내려갑니다.
- 프리뷰 실대화 4건 중 3건(짧은 질문)은 **도구가 아예 호출되지 않았습니다.** 라우팅과는 별개 사안이라 이 문서에서는 다루지 않았습니다.
- 원인 3개 중 **①만 고쳤습니다.** ②(`hay`에 근거법 전문)·③(어절 조사 매칭)은 손대지 않았습니다 — ①만으로 18개가 전부 통과해 필요가 없어졌습니다. 다른 계열에서 오라우팅이 다시 나오면 그때 봐야 합니다.
